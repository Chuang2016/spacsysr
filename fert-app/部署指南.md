# 科学施肥 App 部署指南（手机版 / 服务器 / 微信公众号）

## 一、版本说明

| 版本 | 文件 | 适用 |
|---|---|---|
| 电脑版（R/Shiny） | `app.R` + `R/fert_core.R` | 电脑浏览器，需装 R |
| **手机版（H5 单文件）** | `mobile/index.html` | **iOS / 安卓 / 微信内置浏览器**，无需安装，推荐部署此版 |

> 说明：R 语言无法编译成 iOS/Android 原生 App。行业通用做法是把工具做成
> 手机网页（H5）：在手机浏览器或微信里打开，体验接近 App，还可通过
> "添加到主屏幕" 实现全屏图标启动。本 App 的手机版是**单个 HTML 文件**，
> 无需数据库、无需后端，部署极简。

## 二、部署到自己的 VPS（静态托管）

手机版是纯静态文件，任意 Web 服务器都能托管。以 Ubuntu VPS 为例：

```bash
# 1. 登录 VPS
ssh 用户名@你的VPS_IP

# 2. 安装 nginx（Ubuntu/Debian）
sudo apt update && sudo apt install -y nginx

# 3. 创建目录并上传文件（在本地电脑执行）
scp mobile/index.html 用户名@你的VPS_IP:/tmp/
# 回到 VPS：
sudo mkdir -p /var/www/fert && sudo cp /tmp/index.html /var/www/fert/

# 4. 配置 nginx
sudo tee /etc/nginx/sites-available/fert <<'EOF'
server {
    listen 80;
    server_name 你的域名或IP;
    root /var/www/fert;
    index index.html;
}
EOF
sudo ln -s /etc/nginx/sites-available/fert /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

用手机浏览器打开 `http://你的VPS_IP/` 即可使用。

### 一键 HTTPS（推荐用 Caddy，更简单）

```bash
sudo apt install -y caddy
sudo mkdir -p /var/www/fert && sudo cp /tmp/index.html /var/www/fert/
# 把下面的域名换成你自己的（需先把域名解析到 VPS IP）
sudo caddy file-server --domain fert.yourdomain.com --root /var/www/fert
```

Caddy 会自动申请 Let's Encrypt 证书，全程 HTTPS。

## 三、挂接到微信公众号

1. 登录 [微信公众平台](https://mp.weixin.qq.com) → 内容与互动 → 自定义菜单。
2. 添加一级菜单（如"施肥推荐"）→ 菜单内容选 **"跳转网页"** → 粘贴第二步的网址。
3. 保存并发布（24 小时内生效）。用户点菜单即在微信内打开 App。
4. 可选：把网址生成二维码印在宣传单上，扫码直达。

注意：
- 仅"菜单跳转网页"不需要域名备案；IP 地址也能用（建议还是用域名+HTTPS 更稳定）。
- 如需自定义微信分享卡片标题/图标（JS-SDK），才需要已备案域名，属进阶需求。

## 四、让助手直接帮你部署（安全方式）

**不要在聊天里发 VPS 密码。** 标准做法是用 SSH 公钥授权：

1. 登录你的 VPS，运行这一条命令（把助手的公钥加入授权列表）：

```bash
mkdir -p ~/.ssh && echo 'ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIG7AnZTpmKgIILS2w4OJaGYdCnCJqxTEYKkJRWldKAuX hatch' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys && chmod 700 ~/.ssh
```

2. 把 `用户名@VPS_IP`（如 `root@1.2.3.4`）告诉助手。
3. 助手通过 SSH 登录，自动完成 nginx/Caddy 安装、文件上传与配置，你只需最后用手机打开验证。

想收回权限时，从 `~/.ssh/authorized_keys` 删掉这一行即可。

## 五、关于微信小程序

建议先用上面的 H5 版验证需求，确实需要再立项开发。
